# Changelog

Every StoryForgeAI release, newest first. The five most recent also appear in
the [README](README.md#update-log); this file is the complete record and nothing
is ever removed from it.

The version shown in the app's footer is the top entry here.

| Version | Date | What changed |
| --- | --- | --- |
| **1.11** | 2026-08-07 | **Say which model "Automatic" is actually using, and why a model list is empty.** Leaving a model on **Automatic (best ranked)** gave no clue what would render — the ranking is real, but it is invisible, so there was no way to tell a sensible default from a wrong one. Both pickers now name the model a render would resolve to, resolved through the same code the renderer uses rather than a second guess at it, and accounting for the substitution that happens when pinned characters need a model that accepts reference images. Separately, an empty picker used to read "0 of 0 shown" whether WanGP had no such models or was not running at all — two very different problems that look identical from the catalogue. The screen now says which it is, and names the address it tried. |
| **1.10** | 2026-08-07 | **Hold a character's face for the whole clip, not just at its two ends.** A clip built from a start and an end frame can let a character deform through the middle of the shot and arrive correct again at the finish, and face-swapping the keyframes cannot touch it — the keyframes were never the problem. Where MiniMax H3's **reference** checkpoint is installed, project settings now offers it as a second way of giving H3 the shot: the two frames go in as references rather than anchors, alongside one photograph of each character present, and the likeness holds for the full clip. A live 13.7-second run held identity throughout and lip-synced its dialogue. It is a deliberate choice, not a default, because it costs about three times as much time — the screen states the estimate for your cast before you pick it — and caps clips at 14 seconds, this variant having no stitching to render past that. It refuses rather than degrades: one keyframe instead of two is refused, since a single anchor was measured losing the composition entirely, and a fourth character in a scene is reported rather than quietly dropped. |
| **1.09** | 2026-08-07 | **Accelerator LoRAs named with underscores now run at the step count they were built for.** A LoRA whose filename says how many steps it needs — `4step`, `8_steps` — has that number read off it, because running a distilled LoRA at the model's full count throws away the time it exists to save. The pattern only matched when the count was set off by a dash or a space, so MiniMax H3's `minimax_h3_turbo_4step` was missed and its clips ran at twenty steps instead of four: **five times the wait**, for a picture the LoRA was never tuned to produce. Any accelerator whose filename separates the count with an underscore was affected. |
| **1.08** | 2026-08-06 | **A permanent changelog, and MiniMax H3's own prompt format behind a flag.** The update log below only ever shows five releases, so everything older used to fall off the end and vanish; [CHANGELOG.md](CHANGELOG.md) now keeps every release ever made, and the release checks refuse to drop a row from the README unless it is already recorded there word for word. Separately, `H3_NATIVE_PROMPT_FORMAT` sends H3 the labelled structure MiniMax publishes rather than one paragraph of prose. It stays **off**: three live A/B pairs each showed the labelled arm producing no spoken dialogue at all, where plain prose said the line correctly every time. What the testing fixed along the way, and what everyone gets: H3 writes its own soundtrack and was being given no audio direction at all, so it invented one and **sang a line the scene had only asked it to say** — ambience and score now always reach it; and clip prompts for H3 are now written at the length MiniMax ask for rather than a third of it. Also fixed: the cap that holds H3 at 480p for upscaling was being reported and then discarded whenever a caller passed no frame settings. Every path in the app passes them, so no render was affected — but the log was claiming a clamp the job would not have got. |
| **1.07** | 2026-08-06 | **MiniMax H3 prompting corrected against MiniMax's own guide, plus two fixes found while checking it.** A live schema dump showed H3 declares no negative prompt at all, so every exclusion written for an H3 clip — flicker, identity drift, the terms your pinned characters contribute — was being discarded on the way to the renderer; those now travel inside the prompt as the thing to show instead, the way they already did for FLUX. The single-pass clip length was also wrong: H3 renders about **15 seconds** in one pass, not the 20 the settings screen claimed, so a 20-second clip was being stitched from overlapping passes without saying so. Pinning an H3 **Ref2VA** model is now refused rather than quietly dropping both keyframes and rendering from the prompt alone — FL2VA is the variant that takes a start and end frame. The prompt guidance itself now follows MiniMax's published camera vocabulary and keeps ambience, audience-only score and speech as the three separate layers H3 expects. |
| **1.06** | 2026-08-06 | **Replaced frames now actually appear on the storyboard.** A frame swapped in place — an imported image, a face swap, the carried-over start frame that goes with it — kept the same media address, so nothing told the browser the picture behind it had changed and the scene went on showing the old one. The record was right and the screen was wrong, which is the worst way for it to be wrong. Each image and clip is now addressed by its content, so a replacement is visible as soon as the card reloads. The scene card also stops claiming the following scene was updated unless it can see that it was. |
| **1.05** | 2026-08-06 | **Import a keyframe instead of rendering one.** Sometimes the picture already exists — a photograph, or StoryForge's own render taken away and edited — and no amount of re-rolling a seed will get the model back to it. Each scene card now takes an image for its start or end frame, and everything downstream reads it: the end-frame reference, the clip, and the next scene's carried-over start frame, which is replaced along with it where the project carries end frames forward. The card says what the import costs: the pinned seed no longer describes that frame, and **Regenerate media** re-renders both frames and throws the image away — **Regenerate video for selected scenes** rebuilds the clip and keeps it. |
| **1.04** | 2026-08-05 | **MiniMax H3 support, and a fix for every video model.** H3 was unrecognised, so its clips were prompted with no guidance at all and nothing was written for the soundtrack it generates from the same prompt — it now gets both. Keyframe and clip resolution are separate settings, since a slow video model is no reason to render the frames that fix identity and wardrobe small; H3 is held at 480p and asks WanGP for the upscale rather than inheriting whatever was last selected there. Clip length is editable after creation and names the length past which a model stitches a clip from overlapping passes. Affecting every project: clip length was being sent to WanGP as an audio setting the model meant something else by. |
| **1.03** | 2026-08-05 | **Copy the previous scene's LoRAs.** Setting the same override on a run of scenes meant picking every LoRA again on each card. Where the preceding scene has its own selection, its LoRA panel now offers **Copy previous scene's LoRAs**, which fills in both the image and video lists so you can save them as they are or adjust first. It is a one-time copy — later edits to the earlier scene leave this one alone. |
| **1.02** | 2026-08-04 | **Per-scene end-frame reference override.** A carried-over start frame is handed to the end-frame render as a reference image, which holds wardrobe and location across the seam — but holds props too, so an action meant to put a glass down left it in shot. **Match the carried-over frame** on the scene card turns it off for that scene alone. Also: corrected the README's claim that clips are a fixed 20 seconds, and added this log. |
| **1.01** | 2026-08-04 | **Live batch progress.** A phased run banks each scene's keyframes as it renders them instead of at the end of the phase, so the storyboard fills in while the batch is still going and cancelling no longer discards hours of finished frames. Per-scene chips now name the phase, the counter reports renders that succeeded with failures listed apart from them, and the clip phase stops calling itself that in a keyframes-only project. |
| **1.00** | 2026-08-03 | Baseline release: the agent crew, storyboard, WanGP media generation, character library and wardrobe timeline, LoRA selection, assembly and export, provenance, durable tasks, and the accessibility pass. |
